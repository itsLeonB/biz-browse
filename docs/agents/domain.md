# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md`: domain terms at the repo root.
- `docs/adr/`: architecture decisions.

Before exploring an area, read the glossary and any ADRs that apply. If either is missing, continue without suggesting that the user create it.

Use glossary terms in issues, proposals, hypotheses, and tests. If a needed term is missing, check whether it is a real gap and note it for `/domain-modeling`.

If a proposal conflicts with an ADR, name the ADR and explain the conflict.
