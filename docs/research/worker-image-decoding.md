# Offline image decoding in Workers

Research for issue #3, checked 2026-11-17. No third-party code was installed or run, and no Worker was deployed.

## Recommendation

**Prototype the three `@jsquash` decoders, but do not ship them as strict validation yet.** They perform real pixel decoding, have an upstream Cloudflare Worker example, and ship offline Wasm. Their stock APIs do **not** establish the requested strict corruption rejection or safe resource bounds. In particular, the JPEG decoder needs a strict error policy, likely a patched/rebuilt codec. If that patch and the tests below are not acceptable, no researched package is proven to meet all requirements; use a purpose-built, maintained Wasm decoder instead of claiming signature checks are enough. [jSquash Worker example](https://github.com/jamsinclair/jSquash/blob/main/examples/cloudflare-worker-esm-format/src/index.js), [JPEG source at published package commit](https://github.com/jamsinclair/jSquash/blob/1f62015f53e28bd18b2d7c8a3ca3326577efc445/packages/jpeg/codec/dec/mozjpeg_dec.cpp).

## Critical validation gaps

- **JPEG can recover from damage.** The published jSquash JPEG source uses `jpeg_std_error` and `jpeg_mem_src` with no visible warning-to-error handler. libjpeg-turbo's memory source warns on premature EOF and inserts a synthetic end marker. A decoded image is therefore not, by itself, proof that a JPEG was complete. Confirm the exact bundled mozjpeg behavior and rebuild with warnings treated as errors if required; checking for an end marker alone does not catch corrupt scan data. [jSquash source](https://github.com/jamsinclair/jSquash/blob/1f62015f53e28bd18b2d7c8a3ca3326577efc445/packages/jpeg/codec/dec/mozjpeg_dec.cpp), [libjpeg-turbo memory source](https://github.com/libjpeg-turbo/libjpeg-turbo/blob/main/src/jdatasrc.c).
- **Define the scope of “fully.”** The WebP wrapper calls `WebPDecodeRGBA` once, not a frame-by-frame animation decoder. PNG decoding also needs explicit APNG policy. Reject animation unless all frames and container data are validated; test corrupt later frames, trailing data, and PNG CRCs. A pixel decode alone cannot prove that every byte or ancillary chunk is valid. [WebP wrapper](https://github.com/jamsinclair/jSquash/blob/8bcd212da8c2be7c9c223e8f222eb3d9574a713b/packages/webp/codec/dec/webp_dec.cpp), [PNG decoder source](https://github.com/jamsinclair/jSquash/blob/main/packages/png/codec/src/lib.rs).
- **Bound before allocation.** Enforce a streaming input-byte ceiling, then safely parse format and dimensions before invoking a decoder; reject zero, excessive width/height and pixel count with overflow-safe arithmetic. Header parsing is only a guard, never validation. Budget at least `width × height × 4` for one RGBA image, plus compressed bytes, Wasm memory, copies, orientation buffers and concurrent requests. The JPEG source makes additional full-size buffers for orientation. Use conservative limits and verify decoder internal allocation limits; headers alone do not guarantee a hard memory bound. [JPEG source](https://github.com/jamsinclair/jSquash/blob/1f62015f53e28bd18b2d7c8a3ca3326577efc445/packages/jpeg/codec/dec/mozjpeg_dec.cpp), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).
- **CPU is not stopped by `Promise.race`.** Synchronous Wasm blocks the isolate; a timer cannot interrupt it. Use small input/pixel limits and Worker CPU limits; benchmark worst-case valid and malformed inputs, concurrency and peak memory. Cloudflare documents 128 MB per isolate shared across requests and Wasm, 10 ms/request on Free, and Paid 30 s default / 5 min maximum. Platform termination is not a guaranteed clean validation response. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).
- **Security upkeep is mandatory.** CVE-2023-4863 affected libwebp before 1.3.2. The published WebP package's build recipe pins a libwebp commit, but its exact version and the provenance of the published Wasm were not independently verified. Do not assume the runtime patches bundled Wasm; trace and verify the codec build, monitor codec advisories, and update/rebuild promptly. [NVD advisory](https://nvd.nist.gov/vuln/detail/CVE-2023-4863), [pinned build recipe](https://github.com/jamsinclair/jSquash/blob/8bcd212da8c2be7c9c223e8f222eb3d9574a713b/packages/webp/codec/Makefile).

## Integration and acceptance gate

Install only after review: `npm install @jsquash/jpeg@1.6.0 @jsquash/png@3.1.1 @jsquash/webp@1.5.0`. Import each decoder's `.wasm` as a Worker module and pass it to its `init`; follow the upstream example for JPEG/PNG and verify the WebP decoder path in the actual Vite/Workers build. Do not use a CDN, dynamic remote fetch, or the example's external image fetch. Wrangler bundles `.wasm` as `WebAssembly.Module`; generated glue and TypeScript declarations may need build configuration. [Example](https://github.com/jamsinclair/jSquash/blob/main/examples/cloudflare-worker-esm-format/src/index.js), [WebP init](https://github.com/jamsinclair/jSquash/blob/main/packages/webp/decode.ts), [Cloudflare Wasm bundling](https://developers.cloudflare.com/workers/runtime-apis/webassembly/javascript/).

Before storing bytes, require successful strict decode and a matching detected type. Test valid examples of all three formats, misleading MIME/signatures, truncated files at multiple offsets, damaged image data/checksums, huge dimensions, decompression bombs, animation policy and concurrent uploads. Measure local Worker CPU, memory and bundled size; do not claim production fit until measured. The existing storage path writes supplied bytes and content type to R2; validation must happen before that write. [Storage path](../../src/server/photos.server.ts), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).
